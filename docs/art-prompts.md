# 美术素材提示词与规格

> 用途：给 AI 绘图（即梦 / 豆包等）或外包美术的**可执行交付规范**。
> 目标：拿到的图可以直接接入游戏，不需要返工。

## 一、为什么不能直接画"成品甜品"

游戏的每个杯子由 **4 个独立层块** 竖向堆叠而成，绘制时每层是一个固定尺寸的矩形贴图。
所以每种口味需要的是**一层奶油/果冻切块**，而不是"一杯做好了的甜品"。

错误示例（不可用）：整杯甜品、带边框的卡片、带碗的成品、一团没有层感的奶油。
正确示例（可用）：**单个、正面、无容器、占满画布、四角透明的层块贴图**。

## 二、尺寸与格式规范

按 750 设计宽的 **2 倍**导出（脚本会自动缩放到目标尺寸，源图大一些更保险）。

| key | 逻辑尺寸 | 建议源图 | 说明 |
| --- | --- | --- | --- |
| `bowl.body` | 132 × 240 | 528 × 960 | **空杯**，杯口敞开，杯内透明（层块会画在它上面） |
| `layer.<口味>` | 114 × 47 | 456 × 188 | 单个层块，四角透明，横向铺满 |
| `bg` | 750 × 1400 | 1500 × 2800 | 全屏背景，会被拉伸铺满屏幕，**不要放文字/logo** |

- 格式：**透明 PNG**（`bg` 可以不带透明）
- 不允许：文字、水印、署名、边框、阴影投到画布边缘、多元素拼图
- 每个素材**画面居中、占满画布**，四周留白不超过 8%

### 为什么层块是 114 × 47

```
杯格 132 × 240
pad = 132 × 0.07 ≈ 9.2       → 内宽 = 132 − 2×9.2 ≈ 113.5
rim = 240 × 0.07 = 16.8      → 内高 = 240 − 2×9.2 − 16.8 ≈ 204.7
每层高 = 204.7 / 4 ≈ 51.2，绘制时再减 4px 间隙 → ≈ 47
```

层块本身请**自己画好圆角**（圆角约 8 逻辑 px，源图约 32 px）并在四角留透明，脚本不负责切圆角。

## 三、需要交付的 13 张图

### 1. 空杯（1 张）

```
单个空的透明玻璃布丁杯，正视图，微俯视，杯口敞开，
杯身圆润、杯壁有柔和高光，杯内完全透明（不要任何甜品、不要液体），
浅奶油色描边，卡通扁平风，柔和粉彩光影，
主体居中占满画布，纯白背景，无文字、无水印、无装饰、无投影
```

### 2. 口味层块（11 张）

每个口味一张，**只替换括号里的口味和颜色**：

```
单个方形蛋糕奶油夹层切片，正视图，纯正面不倾斜，
（草莓味，浅粉色 #FF9DB5 为主，奶油质地，表面有细腻光泽和高光）
圆角矩形，边缘圆润，四角透明，
卡通扁平风，柔和粉彩，浅色柔和描边，
单层，不要碗、不要盘子、不要水果装饰、不要多个层叠，
主体居中水平铺满画布，纯白背景，无文字、无水印、无边框
```

按下面的口味与主色逐张替换：

| 文件名 | 口味 | 主色 |
| --- | --- | --- |
| `layer_strawberry.png` | 草莓 | `#FF9DB5` |
| `layer_mango.png` | 芒果 | `#FFC46B` |
| `layer_cocoa.png` | 可可 | `#B98A65` |
| `layer_matcha.png` | 抹茶 | `#9FD58F` |
| `layer_blueberry.png` | 蓝莓 | `#8FA8E8` |
| `layer_vanilla.png` | 香草 | `#F2DFAF` |
| `layer_caramel.png` | 焦糖 | `#E0A05C` |
| `layer_cherry.png` | 樱桃 | `#E86A7A` |
| `layer_lemon.png` | 柠檬 | `#F3E06E` |

> 只有颜色不同、形状完全一致，堆叠时才整齐。**建议先定一张母版，再用同样构图重绘其余 10 张。**

### 3. 背景（1 张）

```
柔和奶油色竖向渐变背景，顶部 #FFF8F0 渐变到底部 #FFEEDF，
点缀极淡的白色和浅粉色圆斑，极简、干净、无任何主体元素，
竖屏构图，无文字、无水印、无边框
```

## 四、接入流程（三步）

```bash
# 1. 把美术交付的图放进 art_src/（文件名按上表，或用中文名也行）
mkdir -p art_src

# 2. 校验（只检查，不写文件）
npm run art:check

# 3. 缩放 + 生成 manifest 条目
npm run art:ingest
```

脚本会自动：

- 按文件名识别 key（支持 `strawberry.png`、`layer_strawberry.png`、`草莓.png`）
- 白底自动转透明（只去掉与画面边缘连通的白底，保留内部白色高光）
- 等比缩放并居中放进目标画布（**不拉伸变形**）
- 写入 `assets/images/` 与 `assets/manifest.json`
- 报告尺寸、透明度、宽高比偏差、疑似残留水印

产出后 `npm run build` 即可，**游戏逻辑一行都不用改**。

## 五、验收标准

| 检查项 | 通过条件 |
| --- | --- |
| 层块数量 | 11 张，缺哪个口味脚本会报错 |
| 透明通道 | 层块与空杯必须含透明像素 |
| 宽高比 | 与目标比例偏差 ≤ 15% |
| 画面占比 | 主体内容占源图面积 ≥ 55%（四周留白不过多） |
| 水印 | 右下角区域检测不到文字痕迹 |
| 风格一致 | 11 张层块的描边粗细、圆角、光照方向一致 |

## 六、常见返工原因

1. **画了整杯成品** → 无法拆层，必须重画
2. **各自形状不同** → 堆叠后边缘错位，需按母版重绘
3. **带文字/水印/边框** → 上线审核不过，且脚本会报警
4. **主体太小** → 四周留白过多，进游戏后层块看起来是空心的
5. **颜色超出主色** → 与 `theme.ts` 的占位色差异过大，提示高亮时反差不足
